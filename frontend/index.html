Problem Statement vs. Reviewr Architecture

Why Disparate Customer Feedback Fails Today

Local restaurants, YouTube creators, and mobile developers are drowning in raw unstructured comments across incompatible platforms.

❌ The Problem Statement
  • ✕ Siloed Portals: A restaurant chain (e.g., Mani's Dum Biriyani) has reviews locked inside Google Maps; a creator (e.g., VJ Sidhu Vlogs) has comments on YouTube; an app (e.g., Spotify) has feedback on Google Play.
  • ✕ Incompatible Formats: Google Maps has 1–5 stars and branch tags; YouTube has likes, timestamps, and nested reply threads with no stars; Play Store has OS versions and device models.
  • ✕ Duplicate & Quota Exhaustion: Continuous polling without composite constraints triggers redundant database entries and exhausts third-party API quotas.
  • ✕ Unstructured Chaos: Business owners cannot tell what's causing 1-star drops (e.g. weekend wait times vs. brinjal curry taste) without manual parsing.
✨ How Reviewr Solves It
  • ✓ Unified Feedback Normalization: Maps, YouTube, and Play Store comments convert into a standardized Feedback schema preserving original timestamps, authors, and metadata JSONB.
  • ✓ Composite Key Deduplication: Enforces (business_id + source + external_id) constraint to guarantee zero duplicate comments and protect quotas.
  • ✓ Tailored Persona Intelligence: Dynamically adapts to multi-location branch filters for restaurants, video episode selectors for creators, and app version metrics for developers.
  • ✓ Chattermill AI Themes Discovery: Automatically organizes thousands of raw feedback items into high-impact sentiment clusters and actionable growth recommendations.
System Architecture

4-Step Reviewr Intelligence Engine

How raw public customer comments transform into verified executive intelligence.

Step 01

Multi-Source Ingestion

Fetches top-level reviews, video comments, and nested reply threads via official Google YouTube Data API v3, Maps, and Play Store APIs.

Step 02

Schema Normalization

Harmonizes ratings, text, author avatars, and platform metadata into a generic PostgreSQL JSONB model.

Step 03

Idempotent Deduplication

Prevents duplicate insertion and preserves API quota limits across recurring 2-hour synchronization cycles.

Step 04

Chattermill AI Themes

Clusters customer feedback into positive/neutral/negative themes, surfacing actionable product insights.
